# 人工复核说明（给参与复核的同学）

评委要求“请人工复核关键业务标签，记录标注者身份类别、分歧及裁决方式”。现在评测集里所有标签都是大模型标的，这一步要靠人。

## 需要几个人、谁来

- **至少 2 人，最好 3 人**，各自独立标注，互相不商量、不看别人的结果。
- 身份如实记录，分三类：**专业客服**（做过客服工作）、**有相关经验**（做过电商、零售、售后等）、**实验参与者**（一般同学）。没有专业客服也没关系，但报告里就写“实验参与者”，不写成专业客服。
- 每人大约需要 **1.5–2 小时**。

## 怎么做

1. 先读一遍 `lingxi/eval/标注规范.md`，标注的定义以它为准。
2. 运行 `node eval/human-review/export.mjs`（在 `lingxi` 目录），会在 `eval/human-review/sheets/` 生成三张表：
   - `1-消费者消息.csv`（120 条）：填主意图、主导情绪、风险。
   - `2-坐席回复.csv`（40 条）：填“是否必须拦下”。
   - `3-多轮会话.csv`（36 个轮次）：根据服务记录，填“必须承认的逾期承诺”“不该再问的信息”“说的是哪笔订单”“能不能说已安排”。
3. 每人复制一份，文件名后面加上自己的代号和身份类别，例如 `1-消费者消息_P1_实验参与者.csv`。用 Excel 或 WPS 打开、填写、另存为 CSV（UTF-8）。
4. 全部填完后放回 `eval/human-review/filled/`，告诉开发者。之后由脚本计算：人与人之间的一致率与 κ，人与 AI 标注者的一致率；分歧条目列成清单，由团队讨论裁决并记录理由。

## 注意

- 这些是最终测试集。**参与复核的人不要参与改规则**，也不要把题目透露给改规则的人。
- 填写时只看这一条本身（多轮会话看对应的记录），不要上网查。
- 拿不准的条目照样给一个判断，在“备注”里写上“不确定”和原因，比空着更有用。
